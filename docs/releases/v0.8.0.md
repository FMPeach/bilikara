# bilikara v0.8.0 发布说明草稿

状态：待发布。本文汇总相对稳定版 v0.7.2 的变化，也包含 v0.8 预览期间的修复；不表示正式包已经发布。发布前核对最终标签、各平台完整包、升级与原生设备验收，再移除本段草稿标记。公告短文见 [中英日公告草稿](v0.8.0-announcement.md)。

## 升级前请看

从 **v0.8.0-preview.2 及更早版本**升级，请关闭旧软件、备份数据，下载对应系统和架构的**完整包**。这次过渡不要使用旧版本的软件内更新。

- **Windows Preview 2**：把旧版整个 `runtime` 文件夹复制到新版，与 `bilikara-desktop.exe` 放在同一级，再启动。
- **macOS Preview 2**：替换完整的 `bilikara-desktop.app`，保留 `~/Library/Application Support/bilikara/`。
- **Preview 1、v0.7.2 及更早版本**：首次启动检测到旧数据后，核对来源再导入；也可选择旧版 `runtime` / `data` 文件夹。已启动过新版时，可关闭软件后使用完整包中的「导入旧数据」工具。旧格式媒体需重新缓存，手机需重新登记身份；歌单、历史与分场记录通过导入保留。
- 导入工具会保留备份。新版已有记录时另行确认，先备份再替换，不合并两份曲库。不要直接覆盖旧安装或删除原数据。

完整步骤与备份位置见[升级说明](../upgrading.md)。下载入口：[GitHub Releases](https://github.com/VZRXS/bilikara/releases)。

## 新增与改进

- **原生桌面后端**：桌面版默认使用 Rust Host 与共享业务核心，安装包不再包含 Python。保留本地／公网 Remote、队列、历史与播放器的既有工作流。
- **找歌与点歌**：支持 Bilibili 链接、BV / av 号和分享文案中的短链接，以及常见 YouTube 单视频链接；搜索、发现与来源浏览使用更紧凑的卡片和分页。
- **本场用户**：Host 可改名、多选、批量拖动和删除；手机可修改自己的名字。同一身份的设备同步名称，已有歌曲、历史和导出仍保留点歌时的名字。
- **来源管理**：UP 主、收藏夹支持排队拉取与进度显示。Host 多选后可拖动排序或拖入垃圾桶移除，顺序重启后保留；拉取期间仍能管理已保存的来源，等待／拉取中的收藏夹也能查看状态。
- **重唱与手机控制**：Host 增加独立重唱键；Remote 竖屏长按切歌向左展开重唱，松手点选或拖到重唱后松手执行，横屏直接显示。缓存未就绪时仍可展开胶囊，重唱保持禁用。首次可用时展示一次展开提示，长按播放图标可查看操作说明。
- **播放抽屉**：点击与滑动共用展开／收起动画。普通按钮上的明确纵向拖动可交给抽屉，轻点仍操作按钮；输入框、滑条、下拉选择与内容滚动保留优先级。进度条第一次点按显示拖拽球，之后才调整进度。
- **音调与音量**：使用 Signalsmith Stretch 升降调，支持显式单曲音量放大至 500%。增加默认关闭的[自动音量实验](../automatic-volume.md)，由 Host 明确设定基准，Remote 仍可手动调整本曲音量。
- **全屏与观众屏**：完善原生单屏全屏、独立观众屏、二维码共享、新点歌和播放操作提示；电脑保留控制界面。双屏需系统的扩展显示模式。
- **歌单导出**：Host 和本地 Remote 可选择本场、指定归档场次或累计历史，导出 CSV、PNG 或多页 ZIP；公网 Remote 不开放导出。
- **更新与维护**：增加公告板与外部桌面更新器，保留手动下载入口。自动检查只检查版本，不自动下载安装；自动检查和预览版选择跨重启保留。
- **公网连接诊断**：连接状态区分等待 Host、建立传输、验证密码、同步状态／身份和就绪。增加有界脱敏诊断，以及由受信任信令服务下发短期凭据的可选 TURN 接口。

## 修复

- 修复 HiRes 切换中断缓存后可能长时间卡住的问题。**HiRes 和清晰度统一在新建下载任务时生效**，已有任务保留原规格，已缓存内容不自动重下；切换下载器或明确重新缓存仍使用相应替换流程。
- 修复原生 HTTP 传输等待响应头／正文时不能及时取消，以及失败尝试被旧状态重新接纳的问题；保留失败状态和明确重试入口。
- 修复继续上一场的提示阻塞运行设置、下载器选项和本地二维码显示的问题。
- 修复首次／每次启动遗漏自动检查、更新操作忙碌时丢失补查，以及原生端口变化后更新偏好丢失的问题。
- 修复来源拉取完成的自动刷新打断多选拖动、待拉取收藏夹无法进入、移除后的占位与迟到结果重新出现等问题。切换功能页／来源标签退出多选，翻页保留选择。
- 统一来源与本场用户的多选、描边、拖动预览和底部工具提示，修复详情页顶部控件被截断及收藏夹滚动区域错误。
- 修复 Remote 未具备播放条件时仍可重唱、滑入重唱过早触发、胶囊动画中切歌键闪烁等问题；长按播放控件与状态文字不再误选文本。
- 修复 Windows 全屏任务栏残留、部分缩放／窄窗口下的布局，以及显示器变化后窗口跑出可见范围等问题；保留退出全屏前的窗口状态。
- 完善 Remote 身份恢复、迟到 ICE 候选、连接代次与过期回调保护，避免旧连接影响替代连接；就绪必须完成认证、首次状态与身份，不能仅凭 ICE 连通判断。

## 使用范围

- **Android 仍为预览版**。共享组件和浏览器测试不等于 Android 实机验收；正式 APK 还需匹配的签名与发布资产，不因桌面 v0.8.0 稳定版而自动成为稳定版。
- YouTube 暂不支持账号登录、直播、仅播放列表链接及受登录／DRM 限制的内容，也不参与 Bilibili 来源、共享曲库或评分流程。实际可用性依赖 Host 的网络和来源服务。
- **可选 TURN 接口已在应用侧实现，独立信令服务仍需配套签发与管理员配置。** 未启用时保留原有直连路径。此次文档与分支推进没有上线 TURN，也不承诺公共 Wi-Fi、AP 隔离或任何场地已恢复可达。TURN/TLS 亦不保证通过所有代理。见[公网网络说明](../internet-remote-network.md)。
- 公网 Remote 的大列表可能有上限，会提示显示条数；完整队列、历史和来源管理以 Host／本地 Remote 为准。点歌与控制仍依赖运行中的 Host，手机网页不能独立播放。
- 自动音量仍为可选实验；实际音响、原生全屏、物理双屏和场地网络均需现场验证。

## 发布时核对

核对最终提交的跨平台检查与解压后完整包，确认 Windows／macOS 的启动、旧数据导入、重启、更新、播放和全屏／双屏行为。不要把开发工件、Linux 浏览器截图或本地 TURN 测试作为所有平台及场地已通过的证据。

正式发布需另行授权：以最终验收提交创建 v0.8.0 标签，由既有发布流程构建并发布资产。确认完整包与下载入口可用后，再将公告草稿转换为新 ID、真实发布时间和 `version: "v0.8.0"` 的公告条目。公告清单与独立 Worker 部署分别操作；本草稿不会触发它们。
